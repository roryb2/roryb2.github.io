## How it's structured

| Layer | What it does |
| --- | --- |
| Staging | Seven models that clean each raw table. |
| Intermediate | `int_orders_with_payments` resolves each order to a total payment and primary method. |
| Marts | **Finance:** `fct_orders`, `fct_daily_revenue`. **Marketing:** `dim_customers`. |

## The details that matter

- `fct_orders` is **incremental**, so it doesn't rebuild everything on every run.
- `fct_daily_revenue` fills empty days with `dbt_utils.date_spine`, so trends don't skip dates.
- Custom macros run on **BigQuery and DuckDB**.
- Two custom tests check business logic: every customer has an order, and delivery times are never negative.
- The docs call out real data-quality issues instead of hiding them.
